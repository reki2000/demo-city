# Tokyo Swing（試作）

東京（新宿中心）をウェブスイングで飛び回る WebGL ゲームの試作。
Three.js / WebGL2、操作はオートが既定（手動切替可）。

## 起動
```
python3 -m http.server 8765   # このフォルダで
# http://localhost:8765/
node tests/run.mjs            # ロジック検証（描画なし）
```

## データ方式（A案: PLATEAU軽量化 + ストリーミング）
「全データを圧縮してメモリに持つ」でも「毎回まるごと fetch」でもなく、**両者の2段構成**:

1. **fetch で動的に読む** — 建物は 300m タイル単位。中心タイルが変わった時だけ判定し、
   進行方向のタイルから優先して取得する。全23区（PMTiles で約300MB級）を起動時に持つことはしない。
2. **生データは圧縮してメモリ保持** — 1建物 = footprint矩形 + 高さのみを 0.5m 量子化し
   Int32Array に詰める（**24 byte/棟**、実測 696 byte/タイル）。LRU 121タイルまで保持するので
   戻ってきた場所は fetch なしで即展開できる。
3. **動的展開は近傍だけ** — GPUジオメトリ（InstancedMesh）は半径2タイル（5×5）だけ展開し、
   外れたタイルは dispose する。重いのはジオメトリ展開であって生データではない、という分離。

実データ化の差し替え点は `src/city-data.js` の `generateTile()`:
PLATEAU の MVT（LOD1, 属性 `bldg_measuredHeight`）を fetch してデコードし、
同じ `{data: Int32Array, landmarks}` 形を返せばストリーマー・物理・描画はそのまま動く。
配信は PLATEAU 配信サービスの MVT / 3D Tiles LOD1（CC BY 4.0、出典表記が必要）。

現状のタイル生成はモックだが、新宿のランドマーク（都庁243m、ドコモタワー240m 等）は
実名・実高さで配置し、PLATEAU実データに替えたときの見え方の目安にしている。

## 建物の形状（フットプリント）
建物は直方体ではなく、元データの平面形状（フットプリント多角形）をそのまま押し出す。
- 中心部（半径約1.5km）は **OSM実建物の輪郭**（春日16,498棟 / 新宿15,303棟、タイル単位で
  `src/footprints.js` に焼き込み、生成は `tools/build-footprints.py`）。高さはOSMタグ
  （height / building:levels）を優先し、無い棟だけ中心距離＋ハッシュで推定。
  ランドマークと重なる棟は除外し、東京ドームは楕円フットプリントで表現。
- PLATEAU LOD1 も同じ「輪郭＋高さ」形式なので、この形のまま実データに差し替え可能。
- 当たり判定・屋上着地・壁登りもポリゴン基準（L字の窪みや中庭に入れる）。
- 外周部は従来の手続き生成（矩形）。
- 壁テクスチャは4種のファサード（オフィス格子 / 横帯 / 住宅 / コンクリートパネル、
  各256px・窓の明暗バラつき付き）を棟ごとに割り当て、異方性フィルタで斜め視点も鮮明に。
- 1階（地上4.2m）だけ別テクスチャ: 店舗（看板帯＋ガラス店頭＋扉）/ オフィスロビー
  （全面ガラス＋キャノピー＋植栽）/ 住宅入口（玄関扉＋ポスト＋表札）の3種を棟ごとに割当。
  上層の窓行は帯の境界で途切れないよう連続させている。
- 壁の縁: 上端1.3mのパラペット帯＋各頂点の角柱を石材テクスチャで分離（窓フィールドと別素材）。
- 道路もOSM実データ（春日14,852区間 / 新宿19,369区間、`src/roads.js`、生成は
  `tools/build-roads.py`）: 種別幅の歩道＋車道リボンを描画し、地面の疑似グリッドは廃止。
- 屋上構造物: 塔屋・室外機・貯水タンクを屋根の内側に自動配置（当たり判定付き）。
- 地形もPLATEAU実測: 地形モデル（dem のTIN三角形、7区分をマージ）を10m標高グリッド化
  （`tools/fetch_plateau_dem.py` → `src/terrain.js`、ステージ中心±1700m）。地面はタイル毎の
  起伏メッシュになり、建物は輪郭内の最低標高に土台を埋めて重心標高＋実測高さで載り、
  道路・ラベル・着地/屋上/壁の判定・HUD高度（地表からの高さ）もすべて標高基準。
  実測の起伏は春日で標高 約0〜31m（駅前・ドームのある谷が低く、本郷・白山の台地が高い）、
  新宿で約16〜46m（都庁のある西の台地が高く、東の低地が低い）。
- 全部PLATEAU実測（建物・屋上・道路）: 公式CityGML 2025年版を7区（文京・新宿＋隣接5区）から
  必要メッシュだけ range 取得し、建物は measuredHeight＋lod0輪郭（`tools/fetch_plateau.py`）、
  屋上構造物は LOD2（`tools/fetch_plateau_roofs.py`、高さ基準が製造元で違うので棟ごとに
  measuredHeight と整合する基準を採用）、道路は tran の道路面ポリゴン（`tools/fetch_plateau_roads.py`、
  LOD2区画は TrafficArea 分割面、LOD1区画は Road 直下の面）。解析済みキャッシュは
  `~/workspace/.osm-raw/plateau*.jsonl`。建物は春日18,516棟中18,356棟（99.1%）・新宿15,046棟中
  14,859棟（98.8%）がPLATEAUで、残り約1%はPLATEAUに無い建物のOSM補完。屋上構造物は実物
  9,880基（親ビルへの着座率98.8%検証済み）を優先し、LOD2が無い建物だけ自動配置。
  道路はPLATEAU面があるタイルではそちら、無い所だけOSMリボン。ランドマークは公称高さ
  （例: シビックセンター PLATEAU実測138.5m vs 公称141.7m）。

## ステージ（新宿 / 春日駅前）
画面下のボタン（または `?stage=kasuga` / `?stage=shinjuku`）で切替。既定は春日駅前。
- 春日駅前（文京区）: 春日駅を原点に、文京シビックセンター(142m)・東京ドームホテル(155m)・
  東京ドーム・ラクーア・後楽園駅・水道橋駅を実位置に配置。OSMラベル28件
  （駅10・交差点12・通り6: 春日通り・白山通り・外堀通り・本郷通り・言問通り・不忍通り、
  交差点は春日町・富坂上・壱岐坂下・小石川後楽園入口ほか）。ランドマークの高さ一部は概算。
- 新宿: 従来のステージ。

## 地名ラベル（OpenStreetMap）
Overpass API で新宿周辺の実データを取得し、46件を焼き込み（`src/labels.js`、
生成は `tools/build-labels.py`、取得 2026-10-29）:
駅18（西武新宿・都庁前・代々木・新宿三丁目ほか）、通り14（甲州街道・靖国通り・
青梅街道・明治通り・職安通りほか）、交差点14（西新宿・歌舞伎町・新宿駅東口・都庁北ほか）。
座標は新宿駅を基準点に実距離で変換。色分け: 駅=赤（ポール付き）/ 通り=青 / 交差点=緑。
出典: © OpenStreetMap contributors (ODbL)。建物配置はまだモック格子なので、
通り名と実際の街路の位置は概ねの対応になる。

## 操作
- AUTO（既定）: アンカー選択・リリースを自動。眺めているだけで飛び続ける
- 手動: `A` で切替、スペース長押し=糸を撃つ / 離す=リリース、`Q`/`E` 旋回、タッチ長押し可
- HUD右上のタイルマップ: 緑=展開中 / 黄=生データ保持 / 橙=取得中

## 構成
- `src/city-data.js` — タイル生成（= PLATEAU MVT の受け口）、圧縮保持フォーマット
- `src/tile-streamer.js` — 2段キャッシュ・先読み・dispose
- `src/swing.js` — 振り子物理、アンカー選択、建物AABB衝突（Three非依存・テスト対象）
- `src/main.js` — Three.js 描画、ヒーロー、カメラ、HUD
- `tests/run.mjs` — city-data / streamer / physics の検証

注: ヒーローは赤青のオリジナルデザイン。スパイダーマン自体は Marvel の IP のため、
公開版では名称・意匠の差し替えを前提とする。
